# LT Content：インタビュー → 発表内容（template.md）

成果物は `<LT>/template.md` の1つだけ。形式は `references/template-format.md` に従う（lt-deck の原稿担当がそのまま読む形式）。

| 成果物 | 中身 |
| --- | --- |
| `<LT>/template.md` 第1部 | 話した内容のまとめ（事実）。本人が言ったことだけ |
| `<LT>/template.md` 第2部 | 台本の下書きと時間配分の表 |

`<LT>/` がなければ作る。git commit はユーザーに言われるまでしない。

## 絶対に守ること

- **体験を作り話で埋めない。** 第1部に書けるのは本人が言ったことだけ。Claude が補った言い換え・推測・一般論には `【要確認】` を付け、⑥までに本人に確認して消すか残すかを決める。
- 第2部（台本）にだけある主張・エピソード・固有名詞を作らない。台本で足した補足は第2部の「削る候補」に入れる。
- これからやること（未実行）を、やったことのように書かない。

前回（LT_2）のレビューで元ネタ由来の問題になったこと。同じことを起こさない：

| 起きたこと | 防ぎ方（このスキルの手順） |
| --- | --- |
| 時間配分の表の合計が300秒＝持ち時間ちょうどで、目標の4分30秒を超えていた | ⑤：合計は「持ち時間 − 30秒」以内。表を書いたら足し算する |
| 字数の記載が「約1,500字」と「約1,600字」で食い違っていた | ⑤：Python で数え、字数の数値は文書全体で1つだけ |
| 台本にだけ固有名詞（govulncheck / Dependabot）があり、技術スタックが推測できた | ①で社内か社外かを聞き、⑤で固有名詞を扱う |
| 台本にだけある主張（「知識は学習時点で止まっている」「仕様の照合は人が見る」） | ④⑤：第1部にない記述は台本に入れないか、削る候補にする |
| 「SKILLを使わない」の範囲が第1部（限定なし）と台本（1回目だけ）でずれた | ③で範囲を聞き切る。④で範囲を明記する |
| 別々の事実を「ので」でつなぎ、因果があるように聞こえた | ⑤⑥：理由の言い方を確認する |
| 山場のあとに3つ目の論点が出て主張がぼやけた | ⑥：山場のあとに新しい論点を足さない |
| タイトル行が `# #`、本文が `\*\*` `&gt;` とエスケープ崩れしていた | 書いたあとに機械チェック（⑤の最後） |

## 0. 体制を決める

`ListAgents` で同じディレクトリのピアセッションを確認する。

- **3つ以上ある**：自分は指揮役。次の3役を1つずつ割り当て、`SendMessage` で指示する。
  - **インタビュー役**：①〜③をユーザーと行い、聞き取りメモ `<LT>/notes/interview.md`（質問と本人の回答をそのまま）を書く。ユーザーと話すのはこの役だけにする（質問が重複しないように）
  - **構成役**：interview.md から④⑤を書く。足りない情報はインタビュー役に質問を依頼する（ユーザーに直接聞かない）
  - **聴衆役**：⑥を行い、指摘を `<LT>/notes/content-review.md` に `ID・重要度・箇所・指摘・修正案` の形式で書く。template.md は直接編集しない
- **2つ**：インタビュー役＋聴衆役を1つ、構成役を1つ。
- **ない**：自分で①〜⑥を順に行う。サブエージェントはユーザーが頼んだときだけ使う。

ピアへの指示に必ず入れること：役割、入力と出力の**絶対パス**、完了したら指揮役に `SendMessage` で報告すること、`notes/<役割>.md` に手順メモを残すこと、commit 禁止、体験を作り話で埋めないこと。返事がなければ、相手が承認待ちになっていないかユーザーに確認を促す。

## ① 前提の聞き取り（AskUserQuestion を1回）

`references/interview-questions.md` の「①」の質問を、`AskUserQuestion` の1回の呼び出し（最大4問）にまとめて聞く。

- 立場（職種・年次）
- 最近の仕事（何に時間を使っているか）
- 聴衆：社内か社外か
- 持ち時間
- 話したいことの種（あれば）

項目は5つ、AskUserQuestion は1回4問までなので、立場・聴衆・持ち時間を選択式にし、「最近の仕事」と「話の種」は1問にまとめて Other に自由記述してもらう（質問集の Q4）。答えにない項目は既定値（持ち時間5分、聴衆は未定）で進め、未決事項として残す。

## ② テーマ候補を3案出す

①の答えから、互いに方向の違う3案を出す。各案に次の4つを書く：

| 項目 | 書くこと |
| --- | --- |
| 伝えたいこと | 1文。言い切りの形にする |
| 裏づけになる本人の体験 | ①で本人が言ったことだけ。足りない部分は「③で聞くこと」として書き、作らない |
| 聴衆が持ち帰れるもの | 聞き手が明日試せること・考え方 |
| 公開リスク | 社外で話すと出てしまう情報（実コード、脆弱性、顧客、技術スタックが分かる固有名詞）と、その避け方 |

テーマが体験と結びつかない案は出さない。3案を見せたあと `AskUserQuestion` で1つ選んでもらう（「組み合わせたい」「別案」は Other で受ける）。

## ③ 深掘りインタビュー

`references/interview-questions.md` の「③」の型で聞く。一度に聞くのは2〜3問まで。答えをそのまま記録し、言い換えない。

必ず聞き出すもの：
1. **具体例**：いつ、何をしていて、何が起きたか（1〜2個に絞る）
2. **意外だったこと**：予想と違ったこと
3. **失敗**：うまくいかなかったこと、自分の側の原因
4. **気づき**：そこから何を学んだか（これが「伝えたいこと」の候補になる）
5. **これからやること**：やろうとしていること。**もう始めたか、まだか**を必ず確認する
6. **範囲**：「いつも」「〜のときだけ」など、言ったことが当てはまる範囲

公開リスクのある話（実コード、ライブラリ名、顧客名など）が出たら、話してよい言い方を本人と決めておく。

## ④ 第1部を書く

`references/template-format.md` の第1部の形式で書く。

- 本人が言ったことだけを書く。言い換えは意味を変えない範囲にとどめる
- 推測で補った箇所・一般化した箇所には `【要確認】` を付ける
- 範囲（「1回目のレビューのときだけ」など）を本人の言葉どおりに書く
- 未実行のことは「まだ実行には移せておらず」のように明記する
- 「LTで一番伝えたいこと」は本人の言葉で1文

## ⑤ 第2部の下書き

`references/template-format.md` の第2部の形式で書く。

- **時間**：時間配分の表の合計は「持ち時間 − 30秒」以内（5分枠なら270秒以内）。表を書いたら必ず足し算する
- **字数**：1秒5字で見積もる（270秒なら約1,350字）。パートごとにも「秒数 × 5」字を目安にし、5.5字/秒を超えるパートは削る
- **字数の数値は1つ**：概要と「練習と準備」で同じ数値を使う。台本の実測値（Python で数えた値）を書く
- **固有名詞**：
  - 社外：実コード・ファイル名・サービス名・ライブラリ名・ツール名（技術スタックが分かるもの）・顧客名を出さず、一般的な言い方（「脆弱性スキャンツール」など）にする
  - 社内：③で本人が出してよいと言ったものだけ使う
  - 未定：社外の扱いにしておき、本番前チェックに「社内か社外かを確認」を入れる
- 台本の中身は第1部にある事実から作る。第1部にない補足を入れたら「削る候補」の先頭に入れる
- 主張は1つ。具体例は2つまで。山場（一番伝えたい一文）は削らず、そのあとに新しい論点を足さない
- 締めはタイトル（伝えたいこと）の再掲

書いたら機械チェックする：

```bash
python3 - <<'EOF' <LT>/template.md
import re, sys
t = open(sys.argv[1], encoding="utf-8").read()
part2 = t.split("## 第2部", 1)[1]
quotes = "".join(l[1:] for l in part2.splitlines() if l.startswith(">"))
print("台本の字数:", len(re.sub(r"\s", "", quotes)))
secs = [int(m) for m in re.findall(r"^\|(?!\s*合計)[^|]+\|\s*(\d+)秒", part2, re.M)]
print("表の合計秒:", sum(secs), secs)
for bad in ["# #", "\\*", "&gt;", "&lt;", "&amp;"]:
    if bad in t: print("崩れ:", bad)
print("【要確認】の数:", t.count("【要確認】"))
EOF
```

表の時間を「1分45秒」と書く場合は秒に直して足す（表は「105秒」のように秒で書くと検算しやすい）。

## ⑥ 聴衆役のセルフレビュー → lt-deck へ引き渡す

①で決めた聴衆（社内／社外、知識レベル）になったつもりで台本を読み、次を確かめる：

- [ ] **主張が1つ**に絞れているか（「伝えたいこと」を1文で言えるか。タイトルと締めが同じことを言っているか）
- [ ] **体験で裏づけられているか**（主張を支える具体例が第1部にあるか。一般論だけになっていないか）
- [ ] **聞き手が持ち帰れるもの**があるか（明日から試せること・考え方が1つ言えるか）
- [ ] 第1部にない主張が台本に入っていないか
- [ ] 範囲の限定が第1部と台本で一致しているか
- [ ] 別々の事実を「ので」でつないでいないか／理由が逆の結論に聞こえないか
- [ ] 未実行のことが未実行と分かるか
- [ ] 専門用語に初出で説明があるか
- [ ] 時間の合計が「持ち時間 − 30秒」以内、字数の数値が1つ
- [ ] 社外の場合、公開リスクのある固有名詞がないか
- [ ] `【要確認】` が残っていないか（残っていたら本人に確認する。確認できないものは削る）

指摘があれば直し、`【要確認】` を本人に確認してから引き渡す。

**引き渡し**：ユーザーに次を伝え、lt-deck を使うか聞く（「この template.md からスライドを作って」で lt-deck が動く）。

- `<LT>/template.md` のパス
- 伝えたいこと（1文）、持ち時間、表の合計秒数、台本の字数
- 社内か社外か、発表者名（未定なら「○○」）
- 残った未決事項

lt-deck の「0. 最初にユーザーへ確認すること」（持ち時間・社内か社外か・発表者名）の答えはここで分かっているので、引き渡すときに一緒に渡す。
