# ペインへの指示文の型

`SendMessage`（`notify_when_idle: true`）で、**1通で完結**させる。追加の指示は後から送らなくて済むように、基準と依存をここで書き切る。
パスはすべて絶対パス。相手の作業ディレクトリは自分と違うことがある。

## 作業役・レビュー役

```text
【役割：<役割名>】<一文で何をするか>。私（<指揮役のペイン名>）が指揮しています。

■ 背景
<作業の目的。合格基準（数値で）>

■ 入力（読むもの）
- <絶対パス>：<中身>（編集禁止）
- <使うスキルがあれば名前>

■ 出力
- <絶対パス>：<形式。他の役割やスクリプトが読む形式なら見本>

■ 手順メモ
- <WORK>/notes/<役割>.md に <skill-forge のパス>/references/notes-template.md の型で書く。作業の途中で追記する

■ 進め方・依存
- フェーズ1：<依存なしで今すぐできること>（レビュー役なら：元ネタの事前チェック）
- フェーズ2：<誰の何を受け取ったら始めるか>
- 修正したら、<下流の役割>に影響する差分だけを私に報告する

■ 完了報告
- 終わったら <指揮役のペイン名> に SendMessage で：出力のパス、合格基準の結果、未決事項、手順メモのパス
- 判断に迷う点は、修正案（既定）を付けて私に聞く。返事を待つ間は既定で進め、そう明記する

■ 禁止事項
- git commit しない
- 入力ファイル・他の役割の出力を直接編集しない（レビュー役は指摘のみ）
- サブエージェントを使わない（ユーザーが頼んだ場合を除く）
```

## 検証役（④で使う）

```text
【役割：スキル検証】<スキル名> スキルだけを使って、次の入力から成果物を作ってください。これまでの経緯は伝えません。

■ スキル
- <絶対パス>/SKILL.md（references/・scripts/ も使ってよい）

■ 入力
- <絶対パス>（今回の題材とは別のもの。<更新時刻>の版をそのまま使う。作業中に変わったら私に知らせる）
- 条件：<持ち時間・ペインの数などを変えた場合はここに。関係者のペインしかないときは「ピアを使わず1セッションで」>

■ 出力
- <別ディレクトリの絶対パス>/ に成果物
- <同>/notes/verify.md に次の4項目（作業の途中で追記する）：
  1. 推測で補った箇所（ID：G1…。SKILL.md の行番号、何をどう決めたか）
  2. 詰まった箇所（ID：T1…。症状、どう抜けたか）
  3. 合格基準の結果（1つずつ、満たしたか。「実際に動かした」か「コードを読んだだけ」か）
  4. 使わなかった・役に立たなかった部分
  （改善案があれば各項目に添えてよい）

■ 完了報告
- <指揮役のペイン名> に SendMessage で：成果物のパス、合格基準の結果、verify.md の要点（推測と詰まりの件数）
- 判断に迷う点は既定で進めて「推測で補った箇所」に書く（指揮役への質問はユーザーの意図に関わる点だけ）

■ 禁止事項
- スキル本体を編集しない（直したい点は verify.md に書く）
- <元の作業の退避先>・元の作業の notes/・指揮役の検証メモを読まない
- サブエージェントを使わない
- git commit しない
```

## 送る前の確認（検証役）
- [ ] 検証役は①〜③に関わっていないペインか
- [ ] 出力先に旧成果物が残っていないか（`ls` で確認した）
- [ ] 入力の版（更新時刻・ハッシュ）を記録したか
- [ ] 見せないもの（退避先、元の notes/、指揮役のメモ）をすべて禁止事項に書いたか

## 送る前の確認
- [ ] パスはすべて絶対パスか
- [ ] 合格基準が数値か、確かめ方が書いてあるか
- [ ] 完了報告の宛先（ペイン名）が書いてあるか
- [ ] フェーズ1（待たずに始められること）があるか
- [ ] 相手が `from-mode="prompting"` なら、受信が承認待ちになりうることをユーザーに伝えたか
