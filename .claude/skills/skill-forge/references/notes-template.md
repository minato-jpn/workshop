# 手順メモの型（各ペインが `<WORK>/notes/<役割>.md` に書く）

目的：このメモから、次回の人が同じ作業を再現できるスキルを作る。作業の**最中に**追記する（終わってから思い出すと詰まった点が抜ける）。
書き方：具体的な数値・コマンド・ファイル名をそのまま書く。「その回だけの事実」には「（今回）」と付ける（スキル化のときに外しやすくする）。

---

```markdown
# 手順メモ：<役割>（<ペイン名>、<日付>、<作業名>）

## 前提
- 入力：<絶対パス>（編集してよいか）
- 出力：<絶対パス>
- 使ったスキル・ツール：<例：html-ppt、headless Chrome、Python>

## 手順
1. <やったこと>。<なぜその順番か>
   - （今回）<具体例>
2. …
（やり直した手順は消さずに「最初は〜したが、〜のため〜に変えた」と書く）

## 判断基準
- <迷ったときに何で決めたか。数値の基準があれば数値で>
- <誰の指示を優先したか（指揮役・他の役割・元ネタ）>

## 詰まった点
- <症状> → <原因> → <どう抜けたか>
  （例：`wc -m` で全角の字数がずれた → ロケール → Python の len で数えた）

## 繰り返した計算・照合
- <手で2回以上やった計算や突き合わせ。入力・出力・使ったコード>
  （scripts/ にする候補。今回の出力値も書く：照合に使う）

## レビューで得た教訓
- <指摘ID>：<指摘の要点> → <次から最初にやること>

## 他の役割への要望
- <役割>へ：<こうしてくれれば手戻りがなかった>（例：原稿担当へ：修正はスライドに載る文言の差分だけ送ってほしい）

## 出力の形式
- <成果物の固定形式。他の役割やスクリプトが読む形式なら、見本をそのまま貼る>
```

---

指揮役のメモ（`notes/coordinator.md`）は、上の「手順」「判断基準」「詰まった点」に加えて次を書く：
- ①定義の表（対象・入力・出力・合格基準・役割・ペイン割り当て）
- 決めた基準（日付・決定者・置き換えか追加か）
- 通知のやりとりで起きたこと（承認待ち、二重通知、返事がない）
- scripts/ の照合結果
